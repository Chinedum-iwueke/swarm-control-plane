# ALPHA-012 Typed Deterministic Strategy Authoring

## Objective

Reduce failed strategy-engineering work and hosted-token waste without weakening the
scientific or independence gates. Repetitive integration is deterministic; Codex is
used only where the research question requires actual signal logic and again, under a
separate read-only invocation, for independent engineering review.

## Governed sequence

1. A deterministic feasibility preflight validates the complete research handoff.
2. A frozen `StrategyIntent` binds the question, predictor, target, horizon, direction,
   timing, mechanism, basket, immutable data identities, representation graph, window,
   parameter budget and no-capital authority.
3. A deterministic scaffolder creates the exact card, YAML, strategy module,
   documentation and focused-test paths.
4. Codex may replace only explicit unresolved placeholders. Intent mutation, path loss
   and remaining placeholders fail closed.
5. The generated focused test module runs in Bulletproof's pinned scientific runtime.
6. A separate read-only Codex invocation reviews the patch.
7. The complete Bulletproof validator runs once through the existing workflow.
8. Existing strategy-spec and causality reviewers remain independent.
9. Only the classic Bulletproof route may produce and publish a terminal BT-009
   positive, negative, invalid or failed outcome.

## Generic native boundary

Generated YAML declares one confined evaluator at
`src/bt/strategy/<strategy_name>.py:evaluate_alpha_intent`. The compiler and runner
reject path escape, another function name, missing strategy registration, missing or
reordered variants, undeclared parameter selection, absent held-out evidence, missing
metrics or unsupported terminal outcomes. Existing hand-written strategy-family routes
retain their prior artifact and held-out semantics.

## Evidence

- Worker focused and policy tests: 60 passed.
- Complete worker suite: 464 passed.
- Bulletproof authoring, compiler, assignment, funding and cross-sectional regression
  surface: 100 passed.
- The first broad Bulletproof run found two compatibility regressions in established
  evidence semantics. Both were corrected and their exact tests passed; the full suite
  was intentionally interrupted after 195 tests because it is a long-running compute
  workload, not represented as a complete-suite pass.

## Authority boundary

Scaffolding, synthetic tests and engineering review do not establish alpha or produce
a scientific receipt. A genuine BT-009 receipt requires registered real data, a frozen
production commit, independent review and classic Bulletproof execution. No component
in this milestone receives order, capital, shadow-promotion or self-approval authority.
